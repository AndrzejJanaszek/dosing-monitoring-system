# Log events

Every log line has an `event` name from this catalogue. The names are constants in `dms.logs.events`; a test checks that the code and this file list the same events. A new event needs a row here.

| event | level | fields | meaning | action |
|---|---|---|---|---|
| `service.started` | INFO | `run_id` | The service finished startup and is collecting data. | none |
| `service.stopped` | INFO | `run_id` | The service shut down cleanly. | none |
| `service.stop_incomplete` | ERROR | `run_id` | The service stopped after a crash, a thread did not finish in time or the writer lost records; `run.stopped_at` stays empty and the process exits with code 1. | read the preceding errors |
| `config.invalid` | CRITICAL | `errors` | A configuration file is missing or invalid; the process exits with code 2. | fix the files named in `errors` |
| `db.connect_retry` | WARNING | `role`, `attempt`, `error` | The database does not accept the connection yet; the process retries. | check that PostgreSQL is running |
| `db.connected` | INFO | `role`, `dbname` | The database connection was established. | none |
| `db.schema_incompatible` | CRITICAL | `database_version`, `package_version` | The database schema does not match the installed package; startup is refused. | run `dms-migrate` or install the matching package |
| `db.startup_failed` | CRITICAL | `step`, `error` | A startup step against the database failed; startup is refused. | read `error`, fix and restart |
| `db.write_error` | WARNING | `error`, `batch_size` or `context` | Writing a batch failed with a transient error; the writer reconnects and retries. | check the database if it does not recover |
| `db.write_recovered` | INFO | `outage_s` | Writing resumed after a transient error. | none |
| `db.readings_skipped` | WARNING | `skipped`, `batch_size` | Some meter or temperature readings of a batch were not inserted because a reading of the same silo, sensor or address and timestamp already exists (for example after the system clock stepped back). | check time synchronisation if it repeats |
| `db.record_rejected` | CRITICAL | `record_type`, `record`, `error`, `fallback` | The database rejected one record (constraint violation or value out of range); the record is not stored, its full content is in `record`, and the rest of the batch is written. For the end of a tank event `fallback` tells whether the row was closed as `incomplete` with `end_quality` `record_rejected` (`closed`), was not found in progress (`no_row`) or could not be closed either (`failed`). | report the record content: it is a bug; a row left `in_progress` is closed as `service_crashed` at the next start |
| `writer.fatal` | CRITICAL | `error` | The writer hit an error that is neither transient nor a rejected record (for example a full disk or a bad statement); the process exits. | read `error`, fix the cause (for example a full disk) |
| `writer.abandoned` | ERROR | `lost_records` | The service is stopping while the database is unreachable; the writer gives up after one last attempt and the records are lost. `run.stopped_at` stays empty and the process exits with code 1. | check the database; the gap in `meter_reading` is expected |
| `engine.fatal` | CRITICAL | `error` | The engine hit an unexpected error; the process exits. | report the traceback |
| `thread.crashed` | CRITICAL | `thread`, `error` | An unhandled exception ended a thread; the process exits with code 1. | report the traceback; systemd restarts the service |
| `port.opened` | INFO | `device_id`, `port` | A serial port was opened. | none |
| `port.open_failed` | WARNING | `device_id`, `port`, `error` | A serial port cannot be opened; logged on the first failure of a series. | check the cable and the configured port path |
| `port.disconnected` | WARNING | `device_id`, `port`, `error` | Reading from a serial port failed; the adapter reconnects. | check the cable |
| `port.silence` | WARNING | `device_id`, `port`, `silence_timeout_s` | No frame with data arrived within the silence timeout; the adapter forces a reconnect. | check that the device is powered and sending |
| `port.silence_ended` | INFO | `device_id`, `port`, `duration_s` | A frame with data arrived after a silence. | none |
| `port.garbage` | WARNING; DEBUG for every frame | `device_id`, `port`, `rejected_count`; at DEBUG `frame` (its first 64 bytes) | Frames that do not parse arrive (or exceed the frame length limit); logged at WARNING for the first one and then every 100th, and at DEBUG for each one. | check baud rate and output format of the device |
| `meter.out_of_range` | WARNING | `device_id`, `port`, `status` | The meter reports overload (`OL`) or underload (`UL`); no reading is published, the port counts as alive. Logged when the state starts or changes. | check the load cell and the silo |
| `meter.back_in_range` | INFO | `device_id`, `port`, `status` | The meter sends weights again after an overload or underload. | none |
| `arduino.log` | DEBUG, INFO, WARNING or ERROR (as in the board's prefix) | `device_id`, `port`, `message` | The board sent a log line (`[DEBUG]`, `[INFO]`, `[WARNING]` or `[ERROR]` prefix), for example a banner line after reset; it does not count as data for the silence timeout. | read ERROR lines: the firmware reports a failure in `setup()` |
| `arduino.pins_missing` | WARNING | `device_id`, `port`, `pins` | A `pins` frame lacks configured pins; no signal states are published. Logged when the state starts or the set of missing pins changes. | compare `[[tanks]]` pins with the firmware's `REGISTERED io-pin` banner lines |
| `arduino.pins_restored` | INFO | `device_id`, `port` | A `pins` frame with all configured pins arrived after missing pins. | none |
| `signal.changed` | INFO | `tank_id`, `signal`, `active`, `previous` | A tank signal (`dispense` or `refill`) changed; `previous` is `null` for the first state after startup and for the first state after lost signals. | none |
| `catalog.synced` | INFO | `silos_added`, `silos_reactivated`, `silos_deactivated`, `tanks_added`, `tanks_reactivated`, `tanks_deactivated`, `temperature_sensors_added`, `temperature_sensors_reactivated`, `temperature_sensors_deactivated` | The configuration was written to the catalogue tables at startup; the fields list ids. | check that an unexpectedly deactivated silo, tank or temperature sensor was removed from the configuration on purpose |
| `catalog.identity_violation` | CRITICAL | `tanks`, `temperature_sensors` | Tanks in the configuration belong to a different silo than in the database (items have `tank_id`, `database_silo_id`, `config_silo_id`), or temperature sensors changed their silo or leg (items have `sensor_id`, `database_silo_id`, `database_leg`, `config_silo_id`, `config_leg`; filling an empty leg is allowed). Startup is refused (exit code 1). | restore the silo or leg in the configuration, or give the tank or sensor a new `id` and leave the old one out |
| `silo.reading_stale` | WARNING | `silo_id` | The latest reading of the silo's meter is older than `max_reading_age_s`; the engine creates no records for this silo until a fresh reading arrives. | check the meter's port events (`port.*`) |
| `silo.reading_stale_ended` | INFO | `silo_id`, `duration_s` | A fresh reading arrived after a stale period; `duration_s` counts from the moment the last reading became stale. | none |
| `silo.signals_stale` | WARNING | `silo_id` | No signal snapshot of the silo's tanks arrived within `max_signal_age_s` (counted from the service start until the first snapshot); open events of the silo are closed as `incomplete` with `end_quality` `signal_lost`. | check the board's port and the `arduino.*` events |
| `silo.signals_stale_ended` | INFO | `silo_id`, `duration_s` | A signal snapshot arrived after a stale period; `duration_s` counts from the moment the last snapshot became stale. An active signal now starts an orphaned event. | none |
| `silo.rule_violation` | WARNING | `silo_id`, `type`, `tank_id`, `event_id`, `other_tank_id`, `other_event_id` | An event started while an event of the same type was in progress on the other tank of the silo (`other_*`); the plant should never do this. Both events get `rule_violation` and `collision` when they end. | check the mapping of the board's pins to tanks (`[[tanks]]`) and the wiring of the signals |
| `temperature.sensor_error` | WARNING | `sensor_id`, `error`, `error_code` | A configured temperature sensor changed from a valid reading to an error: `error` is `read_failed`, `power_reset`, `insufficient_power` (reported by the board), `out_of_range` (the value is outside `min_valid_c`..`max_valid_c`; the raw value stays in `dms.temperature_reading`) or `unrecognized` (the board sent a code unknown to the DMS; `error_code` holds it, otherwise the field is absent). Rows with the error are stored; a change from one error to another is not logged again, except that every new unrecognized `error_code` seen during the same error is logged once more (the database keeps no raw code). | check the sensor, its wiring and power |
| `temperature.sensor_error_ended` | INFO | `sensor_id`, `duration_s` | A configured sensor sent a valid reading after an error; `duration_s` counts from the first reading with the error. | none |
| `temperature.stale` | WARNING | `sensor_id` | No reading of a configured sensor arrived within `max_reading_age_s` while frames still come (counted from the service start for a sensor never seen); no rows are stored for it until a reading arrives. | check that the sensor is connected and listed in the board's frames |
| `temperature.stale_ended` | INFO | `sensor_id`, `duration_s` | A reading arrived after a stale period; `duration_s` counts from the moment the last reading became stale. | none |
| `temperature.unknown_sensor` | WARNING | `address`, `error_code` | A temperature frame has a sensor address missing from `[[temperature_sensors]]`; its readings are stored in `dms.unknown_sensor_reading`. Logged once when the address appears; `error_code` is the raw code of its first reading when the DMS does not know it, otherwise the field is absent. | add the sensor to the configuration or remove it from the bus |
| `temperature.unknown_sensor_gone` | INFO | `address` | An address outside the configuration was not seen for `max_reading_age_s`; it is forgotten, so a return is reported again. | none |
| `event.started` | INFO | `event_id`, `tank_id`, `type`, `start_value_kg`, `start_quality` | A tank event (`dispense` or `refill`) started; `start_quality` is `stale_reading` and `start_value_kg` is `null` when the silo's reading was stale at the start. | none |
| `event.orphaned` | WARNING | `event_id`, `tank_id`, `type`, `start_value_kg`, `start_quality` | A signal is active in the first snapshot after the service start or after lost signals; the real start is unknown, so the event starts at the beginning of the unknown period with `start_quality` `unknown` and ends as `incomplete`. | none for a restart in the middle of an event; otherwise check for lost signals |
| `event.completed` | INFO | `event_id`, `tank_id`, `type`, `start_value_kg`, `end_value_kg`, `duration_s`, `delta_kg`, `collision`, `rule_violation` | A tank event ended with fresh readings at both ends; `delta_kg` is the end value minus the start value. `collision` is true when another event of the same silo overlapped it (its `delta_kg` then mixes both events), `rule_violation` when the overlapping event had the same type on the other tank of the silo. | none; for `rule_violation` see `silo.rule_violation` |
| `event.incomplete` | ERROR | `event_id`, `tank_id`, `type`, `start_quality`, `end_quality`, `start_value_kg`, `end_value_kg`, `duration_s`, `collision`, `rule_violation` | A tank event ended without a trustworthy value; `start_quality` is `fresh`, `stale_reading` or `unknown`, `end_quality` is `fresh`, `stale_reading`, `signal_lost` or `service_stopped` (the service was stopped while the event was in progress), and at least one of them is not `fresh`. The row stays in `tank_event` with status `incomplete`. `collision` and `rule_violation` mean the same as in `event.completed`; the times of the signal edges are known even without fresh readings. | check the meter (`port.*`, `meter.*`) or the board (`arduino.*`, `silo.signals_stale`) around the event time |
| `event.crash_closed` | ERROR | `count`, `events` | At startup, tank events left `in_progress` by an earlier run were closed as `incomplete` with `end_quality` `service_crashed`; each item of `events` has `event_id` and `tank_id`. `end_at` is the last meter reading of the silo before this run. | check why the previous run did not stop cleanly (`service.stop_incomplete`, crash, power loss) |
| `migrate.applied` | INFO | `migration`, `schema_version` | One migration file was applied. | none |
| `migrate.done` | INFO | `schema_version`, `applied_count` | All migrations are applied. | none |
| `migrate.checksum_mismatch` | CRITICAL | `files` | An applied migration file was changed; the database is untouched. | restore the files; never edit an applied migration |
| `migrate.database_ahead` | CRITICAL | `migrations` | The database has migrations the package does not know. | install the newer package |
